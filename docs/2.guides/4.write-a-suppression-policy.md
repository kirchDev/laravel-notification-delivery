# Write a suppression policy

Gate 4 is the one gate the package does not own. The default never suppresses anything; binding your own is how an application says "not right now" — see [the gate chain](../1.concepts/2.the-gate-chain.md).

## Steps

1. **Check whether you need one at all.** "Inbox always, live when online, otherwise mail" needs no policy: the inbox is locked and always runs, `live` sets `announce` and the open tab decides whether a toast appears, and a deferred mail is discarded once `read_at` is set. If that is the behaviour you wanted, install `kirchdev/laravel-device-sessions` and stop here — the package binds a presence-aware policy on its own.

2. **Implement the contract.** One method, three possible verdicts.

   ```php
   final class QuietHours implements SuppressionPolicy
   {
       public function decide(object $notifiable, NotificationType $type, Channel $channel): SuppressionDecision
       {
           $local = now()->setTimezone($notifiable->timezone);

           if ($local->hour < 22 && $local->hour >= 7) {
               return SuppressionDecision::send();
           }

           $wakeUp = $local->copy()->startOfDay()->addHours(7);

           if ($wakeUp->lessThanOrEqualTo($local)) {
               $wakeUp->addDay();
           }

           return SuppressionDecision::defer((int) $local->diffInSeconds($wakeUp, absolute: true));
       }
   }
   ```

   `send()` delivers now, `drop()` discards, and `defer($seconds)` hands the channel to a job that re-checks when the delay expires. A delay of zero or less is treated as `send()` — holding something back for no time at all only buys a queue round-trip and a second chance to lose the notification.

3. **Bind it.** Either name the class in `notification-delivery.suppression.policy`, or bind the contract in a service provider. Bind **scoped**, not singleton, if the policy holds any per-request state — the container binds the package's own services that way because Octane workers outlive requests.

4. **Know that only quietable channels reach you.** `decide()` is never called for `inbox` or `live`. A policy does not have to guard against them, and one that tries to suppress `live` is describing a channel property, not a moment — put it in `isQuietable()` instead.

5. **Expect to be asked twice, and answer once.** A deferred channel's job re-runs the chain when the delay expires. If the policy still defers, the job **discards** rather than scheduling again — otherwise a policy that always defers would hold a notification forever, one delay at a time. Design the second answer to be a real verdict.

## Checklist

- [ ] The default behaviour was genuinely not enough — the `if_unread` rule alone covers more cases than it looks like.
- [ ] `decide()` returns `send()` for every case the policy has no opinion about, never `drop()`.
- [ ] Deferrals use a delay the recipient's situation actually changes within.
- [ ] The policy is bound scoped if it caches anything per request.
- [ ] A test covers all three verdicts, including what the deferred job does on the second pass.
- [ ] A test covers a recipient the policy has no data for — no device, no timezone, no profile.
