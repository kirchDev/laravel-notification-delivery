# Add a channel

The package ships `inbox`, `live` and `mail`. Everything else is yours to add — and adding one never means changing this package, because `Channel` is an interface rather than an enum ([why](../1.concepts/3.types-and-channels.md)).

## Steps

1. **Install the channel package** that does the actual delivery. This package deliberately builds none of them: `laravel-notification-channels/webpush` already ships the web-push channel, the subscription table, a `HasPushSubscriptions` trait, VAPID key generation and the cleanup of expired endpoints, and `…/fcm` and `…/apn` cover native push.

2. **Declare an enum implementing `Channel`.** `laravelChannel()` is the bridge — return the third-party channel's class-string, or a channel name Laravel already knows.

   ```php
   enum PushChannel: string implements Channel
   {
       case Web = 'web_push';

       public function laravelChannel(): string
       {
           return \NotificationChannels\WebPush\WebPushChannel::class;
       }

       public function userConfigurable(): bool
       {
           return true;
       }

       // Push interrupts through the OS, so it reaches gate 4 — on a shorter
       // fuse than mail, because a push notification two minutes late is pointless.
       public function isQuietable(): bool
       {
           return true;
       }

       public function isAvailableFor(object $notifiable): bool
       {
           return $notifiable->pushSubscriptions()->exists();
       }

       public function sortOrder(): int
       {
           return 30;
       }
   }
   ```

3. **Answer `isAvailableFor()` honestly.** It is what keeps a settings page from offering a Telegram switch to somebody who never stored a Telegram id — Laravel would silently skip such a channel at delivery time, which is fine for delivery and useless for a UI.

4. **Register the enum** in `notification-delivery.channels.enums`, alongside `CoreChannel`. Where two enums declare the same backed value the first listed wins, so an application overriding a core channel lists its own enum first.

5. **Name the channel in a type's `definition()`** — in `default` to have it on unless the recipient objects, in `available` to offer it switched off, in `locked` to make it unrefusable.

## Checklist

- [ ] The delivery package is installed and configured on its own terms (keys, tables, routing).
- [ ] The enum implements all five `Channel` methods, and `laravelChannel()` resolves to something Laravel can dispatch to.
- [ ] `isAvailableFor()` returns false for a recipient who genuinely cannot receive on it.
- [ ] `isQuietable()` reflects whether the channel interrupts out of band — `false` only if being interrupted is the point.
- [ ] `sortOrder()` places it where you want its column in the settings grid.
- [ ] The enum is listed in `notification-delivery.channels.enums`.
- [ ] A test sends a notification naming the channel and asserts it reaches `via()`.
