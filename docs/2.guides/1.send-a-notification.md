# Send a notification

Three things are yours: the type enum, the notification class, and the recipient's trait. Sending itself is Laravel's.

## Steps

1. **Declare the type**, as an enum case with a stable key. The key is stored on every row, so pick it once and treat it as permanent — see [Types and channels](../1.concepts/3.types-and-channels.md).

   ```php
   enum OrganisationNotification: string implements NotificationType
   {
       case MemberInvited = 'organisation.member.invited';
       case MemberRemoved = 'organisation.member.removed';

       // Static: the group belongs to the enum, not to the case.
       public static function group(): NotificationGroup
       {
           return Group::Organisation;
       }

       // One match, so the parts cannot drift apart and a forgotten case
       // throws UnhandledMatchError instead of yielding no channels.
       public function definition(): NotificationDefinition
       {
           return match ($this) {
               self::MemberInvited => new NotificationDefinition(
                   default: [CoreChannel::Live, CoreChannel::Mail],
                   locked:  [CoreChannel::Inbox],
               ),
               self::MemberRemoved => new NotificationDefinition(
                   locked: [CoreChannel::Inbox],
               ),
           };
       }
   }
   ```

2. **Register the enum** in `notification-delivery.discovery.types`. Sending does not need this — a settings page does, because it has to enumerate types nothing has been sent on yet.

3. **Write the notification** against `TypedNotification`. Implement `type()` and `payload()`; leave `via()` alone, because that is the gate chain's method. `toMail()` and every other channel method stay exactly where they were.

   ```php
   class MemberInvitedNotification extends TypedNotification
   {
       public function __construct(private readonly Organisation $organisation) {}

       public function type(): NotificationType
       {
           return OrganisationNotification::MemberInvited;
       }

       public function payload(object $notifiable): PayloadData
       {
           return new PayloadData(
               name: 'notification.organisation.member.invited',
               payload: ['organisation' => $this->organisation->name],
               actions: [new ActionData('open-organisation', ['id' => $this->organisation->id], 'action.open')],
           );
       }

       public function toMail(object $notifiable): MailMessage
       {
           return (new MailMessage)->line(__('notification.organisation.member.invited', [
               'organisation' => $this->organisation->name,
           ]));
       }
   }
   ```

   `payload()` returns a **translation key and its arguments, never a rendered string**. The inbox translates in the frontend so a language switch takes effect without a reload; mail translates server-side in the recipient's locale. Same key on both sides — and write the test that asserts every type has an entry on both, because without it drift is certain and only the recipient notices.

4. **Give the recipient the trait.** Replace Laravel's `Notifiable` with `RoutesNotifications` plus this package's trait — `Notifiable` is the former _plus_ `HasDatabaseNotifications`, whose `notifications()` relation points at a table this package never writes.

   ```php
   class User extends Authenticatable
   {
       use HasNotificationDelivery;
       use RoutesNotifications;
   }
   ```

5. **Send it**, the way you always did.

   ```php
   Notification::send($user, new MemberInvitedNotification($organisation));
   ```

## Checklist

- [ ] The type key is a value you are willing to keep forever — no class name, no version, no rename planned.
- [ ] `definition()` is a single `match ($this)` covering every case.
- [ ] The enum is listed in `notification-delivery.discovery.types`.
- [ ] The notification implements `type()` and `payload()` and does **not** override `via()`.
- [ ] `payload()` returns a translation key, and the same key exists in the frontend catalogue and the mail locale files.
- [ ] The recipient uses `RoutesNotifications` + `HasNotificationDelivery`, and no longer uses `Notifiable`.
- [ ] A row appears in `delivered_notifications` and `$user->unreadNotificationCount()` moves.
